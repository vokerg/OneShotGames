Locale changes update document language, translatable static nodes, dynamic UI messages, command-card labels, accessibility labels, and viewport-facing copy. Gameplay, simulation, campaign, audio, and save systems remain authoritative for their own state; localization only formats player-facing text.

## Browser/player evidence

The browser localization smoke exercises startup, English and Ukrainian selection, translated shell and mission UI, document-language changes, persistence across reload, fallback behavior, and absence of console/page errors.

Human linguistic review by a native Ukrainian speaker was not performed. Translation refinement can proceed without changing the localization contracts.

## Save implications

No save, checkpoint, replay, or deterministic simulation schema changes are introduced. The selected locale is a presentation preference stored independently with safe fallback when storage is unavailable or malformed.

## AI-system use

Localization does not modify AI observations, doctrine, decisions, command assignment, cadence, or state. It only translates already-produced player-facing labels and messages.

## Limitations

- English is the fallback locale for missing or invalid entries.
- Runtime-created text must use registered translation keys to participate in locale switching.
- Ukrainian copy is functionally complete for the current runtime but still benefits from native-speaker editorial review.
