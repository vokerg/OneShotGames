# UFR-150 — Add profiler and debug overlay

- Pull request: #158
- Branch: `ufrts/UFR-150-profiler-debug-overlay`
- Evidence level: `RUNTIME_INTEGRATED`

## Delivered

- Added bounded, read-only frame profiling at the existing request-animation-frame boundary without changing fixed-step simulation ownership.
- Measures frame delta plus simulation, render, and UI phase time, with latest, average, maximum, and p95 summaries over 120 samples.
- Samples entity, path-service, tactical-AI, audio-voice, memory-proxy, seed, and command diagnostics at most every 250 ms.
- Added an opt-in F3 overlay that starts hidden, ignores editable controls, exposes a read-only diagnostic API, and removes its DOM, styles, listener, and global state on teardown.
- Added explicit unavailable states and fail-closed handling for optional path, AI, audio, and browser heap APIs.
- Preserved the runtime pause/resume contract while rebuilding the task from current `main`.

## Runtime composition evidence

`createGameRuntime` installs the profiler and hidden overlay when the frame loop starts, records each assembled frame, resets history on mission start, and disposes the overlay when the runtime stops. The profiler consumes existing read-only path, AI, audio, command, and clock state; it does not become authoritative for any subsystem.

## Browser/player evidence

Automated browser smoke verifies that the composed application starts and deploys a mission with the profiler installed. Focused DOM tests verify F3 visibility, editable-target exclusion, rendering updates, close behavior, global restoration, and listener/style/root teardown.

Human live-play inspection and workload-specific benchmarking were not performed. Budget thresholds, optimization, and regression closure remain UFR-151 work.

## Save implications

No save, checkpoint, replay, profile, migration, or deterministic simulation schema changes are introduced. Profiler history and visibility are transient and never serialized.

## AI-system use

The profiler reads the tactical-AI snapshot for cadence and summary counters. It does not alter observations, doctrine, decisions, command assignment, update cadence, or AI state.

## Limitations

- The memory value is an approximate deterministic proxy; Chromium heap counters are supplemental and may be unavailable.
- Detailed projections are throttled to 4 Hz while frame timing is recorded every frame.
- Audio metrics remain unavailable until a composed mixer diagnostic exists.
- UFR-150 provides observability, not proof that release performance budgets are met.
