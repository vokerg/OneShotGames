## Delivered

- Thirteen original combat/economy cues covering rifle, machine-gun, cannon, soft and armor impacts, field explosion, vehicle tracks, drone pass, artillery fire, air-defense launch, vehicle destruction, repair, and construction.
- Repository-owned deterministic synthesis recipes with no recordings, sample libraries, generated-model inputs, third-party packages, or network dependency.
- Three compact mono 16-bit PCM WAV banks generated at 12 kHz with a 0.92 peak ceiling and stable cue offsets/durations.
- Versioned combat-SFX manifest with canonical bank hashes, exact cue/event mappings, format metadata, one-shot policy, and complete CC0-1.0 provenance.
- Strict catalog validation for identifiers, bank references, supported audio events, safe paths, cue uniqueness, format bounds, slices, and provenance.
- Exact one-asset UFR-125 policy maps preserving the shared event taxonomy while supplying combat-specific cooldown, concurrency, attenuation, and priority policy.
- Audio-owned runtime that synthesizes and decodes each bank once through the UFR-124 mixer, admits cues through UFR-125, plays declared bank slices, records failures, and supports preload retry.
- Presentation-only `audio.request` adapter with exact disposal and fail-closed containment for malformed payloads or injected playback errors.
- Deterministic build/review tooling and an authoritative verifier stage covering manifest structure, canonical SHA-256 values, WAV headers, PCM format, and clipping limits.
- Focused tests and updated audio ownership, integration, provenance, portability, failure, and extension documentation.

## Self-review corrections

Final semantic and integration review found and corrected:

1. an outdated verifier stage list copied before the latest `main` integration; the current verifier was restored and only the combat-SFX stage was added;
2. false manifest failures caused by trailing-newline and JSON-key-order differences; manifest comparison is now structural while bank bytes remain protected by exact hashes;
3. malformed audio requests that could throw through the domain stream; playback now returns `invalid-request` and the subscriber contains injected failures;
4. sticky preload failures; a later preload can recover after a transient synthesis, digest, or decode error;
5. mandatory runtime hash checking that could reject harmless least-significant floating-point differences between JavaScript engines; canonical hashes remain required in CI and runtime digest checking is optional.
